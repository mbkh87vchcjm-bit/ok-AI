# OK AI — وكيل برمجة شخصي تحت الإشراف

نسخة أولية مفتوحة المصدر لأندرويد، مبنية بـ Flutter. تتيح للمستخدم كتابة مهمة واختيار مزود نموذج عبر API وفتح موقع HTTPS في متصفح مرئي، ثم مراجعة أفعال محددة والموافقة عليها. **هذه ليست بيئة تشغيل مشاريع ولا وكيلًا مستقلًا موثوقًا به دون إشراف.**

> لم يكن أرشيف `personal_agent_github_ready.zip` متاحًا عند بدء هذا المستودع؛ لذلك أُنشئت هذه النسخة من جديد، وليست مراجعة أو إثباتًا لصحة محتويات ذلك الأرشيف.

## ما ينفذه الإصدار

- مهمة، خطة/رد من النموذج، حالة وسجل خطوات؛ بدء وإيقاف مؤقت وتحكم يدوي ومتابعة وإلغاء. عند التوقف أو التحكم اليدوي تُهمل استدعاءات الأدوات القديمة، وتُلزم أدوات النقر والكتابة بقراءة صفحة جديدة بعد الموافقة. عند الإلغاء لا يبدأ الوكيل خطوات جديدة، لكن قد تنتهي عملية كانت قد بدأت بالفعل أو يستمر الموقع نفسه في العمل.
- WebView حقيقي داخل التطبيق، وإدخال رابط موقع يدويًا. تسجيل الدخول وCAPTCHA والتحقق بخطوتين للمستخدم فقط. يوجد كشف تقريبي لبعض نماذج كلمة المرور وCAPTCHA، **وقد يفوته غيرها أو يعطي إنذارات خاطئة**؛ انتقل إلى التحكم اليدوي بنفسك عند الحاجة. لا يتجاوز التطبيق حماية المواقع.
- مزود قابل للاستبدال من خلال واجهة `ModelProvider`؛ التطبيق يطبق حاليًا Chat Completions مع `tools` عبر HTTPS. هذا API منفصل عن موقع المحادثة المفتوح في المتصفح. بعض المزودين أو النماذج لا يدعمون الصيغة أو `max_tokens` المستخدمة.
- أدوات محددة: قراءة صفحة، انتقال، نقر، كتابة نص، حفظ ملف نصي، وسؤال المستخدم. لا توجد أداة لتنفيذ أوامر حرة أو رفع الملفات إلى المواقع أو تنفيذ الكود.
- موافقات صريحة. قراءة الصفحة محليًا تحتاج موافقة، ثم تُعرض البيانات المحدودة وتُطلب موافقة ثانية قبل إرسالها للنموذج. تعرض موافقات الكتابة والنقر والحفظ التفاصيل. الرفض ثابت لنوع الإجراء والنطاق بقية المهمة، ويوقف التنفيذ مؤقتًا؛ محاولة النموذج تكرار الإجراء المرفوض لا تنفذه.
- إذن «مرة»، أو «لهذه المهمة»، أو «قاعدة دائمة» متاح للتنقل فقط وبمطابقة **نوع الإجراء والنطاق والمنفذ**. يمكن حذف القواعد الدائمة من الإعدادات. الأفعال الحساسة، بما فيها القراءة والمشاركة والكتابة والنقر والحفظ، تطلب موافقة لكل مرة حتى لو وُجدت قاعدة قديمة. نطاقات السماح لا تمنح أدوات أو صلاحيات جديدة.
- قواعد مشروع معتمدة يمكن إضافتها وتعديلها وحذفها، أو اعتماد مقتطف من مرجع بعد مراجعته صراحة، ومكتبة مراجع نصية وملفات كود UTF-8، واسترجاع بسيط بالكلمات مع اسم الملف ورقم السطر. تُعاين المقتطفات قبل إرسالها؛ لا يتم إرسال المكتبة كاملة تلقائيًا. يدعم الاستيراد 20 ملفًا كحد أقصى، 64 كيلوبايت للملف و1 ميغابايت للمكتبة. البحث غير دلالي ويعرض مطلع المرجع عند عدم تطابق الكلمات؛ PDF مؤجل.
- بعد انتهاء محادثة ومراجعتك للنتيجة، يمكنك اعتماد تسلسل استرشادي لا يحفظ سوى أسماء أدوات من قائمة ثابتة، دون معاملات أو محددات أو محتوى أو عناوين. يمكن إضافته نصيًا لمهمة لاحقة؛ لا يُنفذ تلقائيًا. هذه الذاكرة والاسترجاع والإجراءات **ليست تدريبًا للنموذج أو تعديلًا لأوزانه**.
- ملفات النتائج في مجلد التطبيق الخاص، ضمن مسارات نسبية محدودة وملفات نصية حتى 64 كيلوبايت. يمكن تصديرها عبر قائمة مشاركة Android. الاستبدال يحتاج موافقة ويُعرض المحتوى قبل الحفظ.

## حدود مهمة قبل الاستخدام

1. **لا توجد بيئة تنفيذ فعلية** أو تشغيل اختبارات أو GitHub داخل التطبيق أو تثبيت حزم أو PDF أو تحليل YouTube. لا تساوي كتابة ملف كود تشغيل البرنامج أو إثبات صحته. قد يخطئ النموذج أو يدّعي الاختبار؛ راجع السجل ولا تعامل نص النموذج كدليل.
2. **لم يثبت توافق أي موقع أو تسجيل دخول أو هاتف بمجرد نجاح CI.** قد تمنع المواقع WebView أو توفر واجهات ديناميكية لا يمكن قراءتها أو نقرها بهذا التطبيق. لا يوجد بديل Chrome مدمج ومختبر في هذا الإصدار؛ استخدام المتصفح الخارجي وحده لا يمنح الوكيل تحكمًا بجلسة المتصفح. لا تتحايل على شروط الخدمات أو وسائل الحماية.
3. الصفحات والمراجع بيانات غير موثوقة وقد تحتوي على حقن توجيهات. قواعد الأمان والموافقات تطبقها الشيفرة خارج النموذج، لكن لا توجد حصانة كاملة ضد الحقن أو أخطاء النموذج أو الصفحات المتغيرة. يُتحقق من عنوان الصفحة وإصدار التحميل قبل النقر، لكن تطبيق ويب قد يغيّر DOM دون تغيير عنوانه.
4. يُحظر التنقل الرئيسي غير HTTPS وعناوين IP والنطاقات المحلية بصيغة الاسم. هذا **ليس جدار حماية أو عزل شبكة**: يمكن لنطاق يبدو عامًا أن يُحل إلى عنوان خاص، وقد تجري الصفحة وJavaScript والإطارات والموارد طلبات لجهات أخرى لا يغطيها فحص التنقل الرئيسي. قد يرسل موقع النص فور كتابته حتى دون نقر «إرسال». استخدم مواقع تثق بها وجهازًا محميًا.
5. قواعد المشروع والمراجع والأذونات والإجراءات تُحفظ في التخزين الخاص للتطبيق **دون تشفير تطبيقي إضافي**. يتضمن تكوين Android `allowBackup=false`، لكنه ليس ضمانًا ضد الوصول على جهاز مخترق أو نسخ أخرى لدى النظام. السجل والمحادثة في الذاكرة فقط. لا تخزّن أسرارًا في المهمة أو المراجع أو القواعد.
6. مفتاح API يُدخل داخل التطبيق ويظل في الذاكرة فقط، ولا يدخل المستودع أو سجلات التطبيق أو رسائل النموذج. يُرسل بترويسة المصادقة إلى عنوان مزود HTTPS الذي اخترته؛ لا يتبع عميل API إعادة التوجيه. لا يلزم أن يرسل التطبيق ملفات جلسة المتصفح أو كلمات المرور إلى النموذج، لكن **النص الظاهر في الصفحة قد يحتوي معلومات حساسة**؛ راجعه قبل الموافقة. لا يمكن ضمان سلوك الموقع أو مزود API الخارجيين.
7. الحدود تشمل عدد الخطوات والمكالمات والأخطاء والوقت، ويمكن ضبط حد تكلفة **تقديري** إذا أدخلت أسعار الإدخال والإخراج. التقدير يعتمد على عدد الرموز الذي يعيده المزود وتقدير قبل الطلب؛ قد تختلف طريقة الفوترة أو تكتمل عملية بعد الإلغاء، وقد تتجاوز الفاتورة الحد. إذا لم يعد المزود معلومات الرموز تتوقف المهمة. اضبط حدًا ماليًا حقيقيًا لدى مزود الخدمة أيضًا. مسح خانة الميزانية يعطل الحد التقديري ويُترك حد عدد المكالمات.
8. تطبيق تجريبي وليس إصدار إنتاج أمني. لا تستخدمه للدفع أو التعامل مع بيانات شديدة الحساسية، ولا تعط أي نموذج أو موقع أو أداة أذونات تتجاوز ما تثق به.

## البناء محليًا

المتطلبات: Flutter **3.27.4**، Python 3، Java 17، Android SDK وAndroid SDK Build-Tools. التطبيق يستهدف أندرويد API 23 فما فوق. لا حاجة إلى حساب جديد أو خدمة مدفوعة للبناء المحلي.

```bash
python3 scripts/bootstrap.py
flutter pub get
python3 -m unittest discover -s scripts -p 'test_*.py'
flutter analyze
flutter test
# اختياري على محاكي أو جهاز متصل:
flutter test integration_test/app_smoke_test.dart
flutter build apk --release
sha256sum build/app/outputs/flutter-apk/app-release.apk
```

`bootstrap.py` ينشئ `android/` باستخدام قالب Flutter مثبت الإصدار دون المساس بـ `lib/` أو المصدر؛ لا يستبدل مجلد Android موجودًا. يضبط الإنترنت، منع HTTP، تعطيل النسخ الاحتياطي، API 23، وAndroid Gradle Plugin/Gradle متوافقين. البناء بوضع **release** لكن قالب Android يوقعه بمفتاح **debug** افتراضي؛ ليس توقيع إنتاج. انظر [إعداد GitHub](GITHUB_SETUP_AR.md).

## التشغيل الأول

1. أدخل رابط Chat Completions الكامل واسم النموذج ومفتاح API داخل صفحة الإعدادات. لا تضع مفتاحًا في URL. أدخل أسعار مزودك لتفعيل حد التكلفة التقديري أو امسح حد الميزانية بعد فهم المخاطر.
2. افتح صفحة HTTPS من تبويب المتصفح، وسجل الدخول بنفسك إن كان الموقع يسمح بذلك. ابقَ حاضرًا للتدخل.
3. أضف مرجعًا نصيًا وقواعد مشروع عند الحاجة. اكتب المهمة واضغط «بدء»؛ راجع البيانات والنطاق قبل موافقة API.
4. اقرأ كل موافقة؛ «تحكم يدوي» يوقف أفعال الوكيل لتتعامل مع الصفحة. بعد المتابعة تحتاج الأدوات إلى قراءة جديدة. يمكنك رفض أي إجراء أو إلغاء المهمة.
5. راجع سجل الأفعال وملفات النتائج؛ صدّر ما تريد من المكتبة. السجل الفعلي منفصل عن ادعاءات النموذج.

## التحقق وحالة الاختبارات

تحتوي `test/` اختبارات للسياسة والأذونات والتخزين وبروتوكول المزود وإيقاف/إلغاء/تدخل الوكيل، وتحتوي `scripts/test_bootstrap.py` على اختبارات تهيئة Android. تحاول مهمة `emulator` تثبيت APK على محاكي Android API 30 وتشغيل اختبارات واجهة وفتح example.org؛ راجع نتيجة المهمة نفسها لمعرفة هل نجحت. شغّلها أو راجع نتيجة تشغيل GitHub Actions المرتبطة بنفس الالتزام؛ وجود الاختبارات في المستودع وحده ليس إثباتًا لنجاحها. نجاح التحليل والاختبارات الآلية وبناء APK لا يثبت التثبيت أو عمله على هاتف أو محاكي أو توافق موقع محدد. راجع أيضًا [قائمة الفحص اليدوي](docs/MANUAL_TEST_AR.md).

## بنية المشروع

- `lib/main.dart`: واجهة المهمة والمتصفح والمكتبة والإعدادات والموافقات.
- `lib/src/agent.dart`: حلقة الوكيل، إبطال الحالات القديمة، الإلغاء والحدود.
- `lib/src/browser.dart`: WebView ونصوص أدوات ثابتة ومقيدة، لا JavaScript من النموذج.
- `lib/src/policy.dart`: التحقق من الروابط والمسارات ونطاقات الموافقات.
- `lib/src/provider.dart`: بروتوكول النموذج والأدوات المنظمة.
- `lib/src/local_store.dart`: تخزين القواعد والمراجع والإجراءات وملفات النتائج.
- `.github/workflows/android.yml`: تحليل واختبارات وبناء، ونشر prerelease يدوي اختياري بصلاحيات كتابة محصورة بمهمة النشر.
